一个给 Kira 机器人用的搜索插件。它通过 **SearXNG**（把多个搜索引擎的结果合并到一起的"元搜索引擎"）帮 AI 做三件事：搜网页、搜图片、抓网页正文。

搜索走你自己的 SearXNG 实例，不经过第三方搜索接口，不消耗别人的搜索额度，也不会因为共用接口被限流。

> 使用前需要一个正在运行的 SearXNG 服务（自己搭的、局域网里已有的都行），并在插件配置里填上它的访问地址。SearXNG 怎么部署见官方文档：<https://docs.searxng.org/>

## 特色功能

- **图片搜索优先**：一次拉回一批候选图，自动去重、检查链接能不能打开、按关键词相关度排序，并剔掉图库站的水印素材图（shutterstock、alamy、gettyimages 之类）。还剩干净图时才过滤，只剩水印图就照常返回，不会给你空结果。
- **发图两种方式**：可以让 AI 自己挑图来发，也可以让插件直接把图发给用户，两种都开也行。
- **网页搜索带分类**：通用、技术、学术、科学、新闻、音乐、视频，按场景挑不同的搜索引擎组合。
- **正文提取**：抓回网页后去掉导航、广告、脚本，只留正文，省模型上下文。
- **与内置搜索互不干扰**：Kira 自带 Tavily / AnySearch 搜索插件可以同时开着，工具名、配置、缓存全部分开。
- **服务层可单独复用**：搜索逻辑是纯 Python 库，不依赖 Kira 框架，想搬到别的机器人框架只要重写一层薄适配。

## 安装部署

**环境要求**

- Kira 3.0.2 或更高版本
- Python 3.10 及以上
- 一个可访问的 SearXNG 实例（默认地址 `http://127.0.0.1:8080`）

**安装**

把插件安装包装进 Kira（插件管理里上传 zip，或把插件目录放进 `data/plugins/` 下），然后在插件列表里启用。依赖会在启用时自动安装。

从旧版本升级不用手动改配置：加载时插件会把不合法的配置值改回默认值并写回配置文件。

网页正文提取用的 `beautifulsoup4`、`readability-lxml` 属于**可选的加强依赖**：装上了提取效果更好；万一没装上，插件会自动改用 Python 自带的解析器，网页搜索、图片搜索照常可用，只是正文可能带一点杂质。

**准备 SearXNG**

SearXNG 需要开启 JSON 输出，否则插件会报"搜索服务返回 403"。在 SearXNG 的 `settings.yml` 里确认：

```yaml
search:
  formats:
    - html
    - json
```

改完重启 SearXNG 即可。

## 配置说明

下表各配置项的含义、默认值和填错后果，与插件设置界面里的提示完全一致。

### 基本设置

| 配置项 | 说明 | 默认值 | 可填范围 / 格式 | 填错会怎样 |
| --- | --- | --- | --- | --- |
| SearXNG 搜索服务的访问地址 | 填你 SearXNG 实例的地址 | `http://127.0.0.1:8080` | 必须以 `http://` 或 `https://` 开头，结尾不要带斜杠。示例：`http://192.0.2.1:8080` | 写成 `127.0.0.1:8080`（缺协议）这类格式会导致搜索失败并提示无法连接搜索服务 |

### 网页搜索

| 配置项 | 说明 | 默认值 | 可填范围 / 格式 | 填错会怎样 |
| --- | --- | --- | --- | --- |
| 每次搜索默认返回几条结果 | 模型没指定条数时的兜底值 | `5` | 1-10 的整数 | 填 0 或负数会被当成 1，填超过 10 会被压到 10 |
| 开启搜索缓存 | 相同关键词在缓存时长内重复搜索直接返回上次结果，减少对搜索服务的请求次数 | `开启` | 开 / 关 | 关闭后每次搜索都会真实请求 |
| 缓存保留时长（秒） | 缓存结果保留多久 | `300`（5 分钟） | 0-86400 的整数，单位秒 | 填 0 表示缓存立即过期（等于不缓存）；填负数会当 0 处理 |

### 图片搜索

| 配置项 | 说明 | 默认值 | 可填范围 / 格式 | 填错会怎样 |
| --- | --- | --- | --- | --- |
| 图片结果怎么交给用户 | 三种模式：**交给 AI 决定（model）** 只把候选图片的链接清单交给 AI，由 AI 自己决定发哪张（最省流量、最灵活）；**直接发给用户（user）** 插件直接把下载好的图片发给用户；**两者都做（both）** 既给 AI 清单，也直接发图 | `model` | 下拉选择，或直接填 `model` / `user` / `both` | 填其他值会被当成 `model` |
| 图片搜索返回几条结果 | model 模式指交给 AI 的候选条数；user 模式单次最多直接发 5 张（防止刷屏） | `8` | 1-10 的整数 | 越界会被压到 1 或 10 |
| 图片搜索一次拉取的候选数量 | SearXNG 一次最多返回的原始图片结果数，拉回来后插件会去重、检查链接是否有效、按关键词相关度排序并剔掉水印素材图，再截取最终条数 | `120` | 10-500 的整数 | 填得越大越可能找到好图，但搜索服务压力也越大 |

### 网页正文提取

| 配置项 | 说明 | 默认值 | 可填范围 / 格式 | 填错会怎样 |
| --- | --- | --- | --- | --- |
| 提取的网页正文最多返回多少字符 | 超出部分会被截断 | `3000` | 200-20000 的整数 | 越界会被压到 200 或 20000；调大能看更多内容，但会占用更多模型上下文 |

### 网络设置

| 配置项 | 说明 | 默认值 | 可填范围 / 格式 | 填错会怎样 |
| --- | --- | --- | --- | --- |
| 单个请求的超时时间（秒） | 超过该时长未返回的请求会被放弃并提示超时 | `15` | 3-120 的整数 | 小于 3 会当 3 处理 |
| HTTP 代理地址（留空则读系统环境变量） | 留空时自动使用系统环境变量 `https_proxy` / `http_proxy` | 留空 | 形如 `http://127.0.0.1:7890` 的地址 | 填错（如缺少协议）会导致连接代理失败、搜索报错 |
| User-Agent（浏览器标识，留空用默认） | 一般不需要改；当某些网站拦截搜索请求时可填任意浏览器 UA | 留空（用内置 Chrome 标识） | 任意 UA 字符串，示例：`Mozilla/5.0 (Windows NT 10.0; Win64; x64)` | 填错只是可能被网站识别为脚本 |

## 使用说明

安装并配置好之后，AI 会自动获得下面 3 个工具（无需手动开关）。

### 网页搜索（web_search）

AI 传入关键词（可选分类和条数），返回 JSON 格式的结果清单，每行一个结果，字段含义：

- `title` 标题
- `url` 链接
- `content` 摘要
- `score` 相关度
- `source` 来源

分类可选：`general` 通用、`technical` 技术、`academic` 学术、`science` 科学、`news` 新闻、`music` 音乐、`videos` 视频；不传默认用通用。

### 图片搜索（search_images）

AI 传入关键词，返回候选图片清单（编号、标题、图片链接、分辨率）。**model 模式下由 AI 决定发哪张**：AI 发送图片时用 `<file type="image">图片链接</file>` 标签即可，插件不会提前下载图片。`user` / `both` 模式下插件会自己下载图片直接发给用户。

候选图的排序方式：先看标题、摘要、图片地址里和关键词对不对得上（命中越多越靠前），对不上的排后面；同样对得上的再比相关度分数和分辨率。

### 网页正文提取（fetch_webpage）

AI 传入网页链接（可选正文长度上限），返回该网页的可读正文。适用于搜索结果需要查看完整内容时。

## 与内置搜索插件共存

Kira 自带的联网搜索插件（Tavily / AnySearch 双引擎）和本插件**可以同时启用、互不干扰**：两边注册的工具名字完全不同，不会覆盖对方；各自的配置和缓存也互相独立。

两边给 AI 的搜索工具会同时出现，分工如下：

| 工具 | 归属 | 定位 |
| --- | --- | --- |
| `search`、`extract_webpage` | 内置插件 | 主力搜索（Tavily / AnySearch 双引擎） |
| `anysearch_batch_search`、`get_sub_domains` | 内置插件 | AnySearch 批量搜索、垂直领域查询 |
| `web_search`、`fetch_webpage` | 本插件 | 备用搜索（走自有 SearXNG 实例，可指定分类） |
| `search_images` | 本插件 | 更快获取图片结果（内置搜索也能发图，但本插件更快） |

本插件的工具描述里已写清楚定位（"作为内置搜索的补充"、"更快获取图片结果的搜索工具"），AI 会据此选择合适的工具：想搜图、发图时优先用本插件的 `search_images`。

## 常见问题

- **搜索提示"无法连接搜索服务"**：检查 SearXNG 地址是否填对、服务是否在运行、网络/代理是否可达。
- **提示"搜索服务返回 403"**：SearXNG 的 JSON 接口没开，或所在网络拒绝了访问。请确认 SearXNG 已开启 JSON 格式输出（`formats` 配置里包含 `json`）。
- **图片搜出来却发不出去**：部分图片链接有防盗链或需要登录，插件会跳过下载失败的图片；`model` 模式下由 AI 决定发哪些，发不出的图换一张即可。

## 项目结构

本插件采用**服务层 / 适配层**双层结构，便于迁移到其他机器人框架，也便于充分测试：

```
kira_plugin_searxng/
├── main.py              # 适配层：读配置、注册工具、翻译 Kira 事件
├── searxng_client/      # 服务层：纯 Python 库，不依赖 Kira 框架
│   ├── http.py          #   HTTP 客户端（可注入，方便 mock）
│   ├── searxng.py       #   搜索入口（网页 / 图片）
│   ├── images.py        #   图片去重、相关度排序、水印过滤
│   ├── fetch.py         #   网页正文提取
│   ├── cache.py         #   TTL 缓存（可持久化）
│   └── ...              #   模型、错误、格式化、分类策略
├── schema.json          # 配置项定义（界面文案与提示）
└── manifest.json        # 插件信息
```

服务层不导入任何 `core.*`，所有外部依赖（HTTP 客户端、日志、缓存时钟、配置）都通过构造参数注入，测试可以完全脱离 Kira 运行。
